# ADR-006: atomic loose-source import

Status: selected for the JavaScript/Python/C# loose-file import batch; Windows acceptance remains open.

Use a dedicated native multi-file picker to copy 1–32 local UTF-8 `.js`, `.py` and `.cs` files into an active logical folder or workspace root. The renderer supplies destination identity, expected workspace revision and an explicit numbered-copy conflict option; it cannot supply source paths. The host's general renderer command channel does not permit import. Extensions are matched ignoring case, source names come from the filename without its last extension, and all existing logical name rules apply. No directory recursion, archive merge, dependency installation, hooks or script execution is introduced.

Import assigns new identities and independent managed source revisions. It preserves original file bytes exactly, including UTF-8 BOM, Unicode and CRLF, without encoding detection/conversion. New v4/v5 scripts get empty tags/favourite false; old workspaces retain their schema without upgrade. Existing folders/scripts/recycle records/collections and source revisions remain unchanged. Original external paths are not persisted as portable metadata.

Preflight the expected revision/manifest, active destination, unique normalized selected paths, supported extension, valid name, symlink/junction restrictions, strict UTF-8 and per-file 256 KiB limit. At most 32 files retain at most 8 MiB in memory. Default name conflicts reject the entire batch before staging. Explicit numbered-copy mode resolves case-insensitive sibling conflicts in selection order using ` (2)`, ` (3)` and so on, truncating the base within 120 UTF-16 units without splitting a surrogate pair. Deleted-script names do not reserve active names; later restore uses existing explicit conflict handling.

Validate the full candidate manifest, catalog/size and next-revision limits before writing any managed source. Stage every new revision, recheck selected-source and staged-copy hashes and manifest freshness, then publish all new records through one manifest replacement. Missing/changed inputs or late failures never overwrite originals or existing workspace records. A late failure/process termination may leave ignored unreferenced copy directories; the recovered manifest exposes either the complete batch or none. Preserve leftovers using existing copy-on-write recovery; there is no automatic pruning or retry.

The UI imports into the current active folder/root and provides the numbered-copy checkbox. Imports preserve the open editor and unsaved source/label drafts; current filters may hide new records and source-search results become stale after the revision changes. Picker cancellation or rejection preserves the current state. Bulk import has a 30-second desktop request deadline; lost responses may have committed, so reopen/inspect before retrying. Local path checks and file hashes detect ordinary edits and accidental links, not hostile filesystem races.

This satisfies the loose-source entry path for v1. Archive merge, arbitrary encoding conversion, recursive directory/provenance import and historical backup retention are separate optional enhancements. Current-state archive export/fresh-folder restore remains the v1 backup path. Editor/formatter/runner/recovery and Windows/final-product acceptance still require their own evidence.
