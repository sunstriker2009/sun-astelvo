# ADR-005: verified workspace snapshot archives and fresh-folder restore

Status: selected for initial export/restore; loose-file import/merge and Windows/clean-machine acceptance remain open.

Use .NET ZIP support to export a saved workspace snapshot and restore it into an existing empty local folder. The archive carries exact `workspace.json` bytes and one current referenced source revision for every script across the active library, script recycle bin and deleted folder trees. This retains schema/IDs, folder relationships, classification and collections without migration. Historical/unreferenced source revisions, upgrade checkpoints, temp files, writer locks, session indexes and unsaved editor/label drafts are outside the snapshot.

Export checks the expected revision and manifest/source integrity, writes a unique temporary archive beside the requested new output, closes/flushed ZIP content, reopens/verifies its entries/CRC/schema/source hashes/UTF-8, rechecks original metadata/source, then renames without overwrite. Existing archives are never replaced. Export output must be outside the active workspace. Failed ordinary exports remove their temporary file; process termination can leave an ignored temp. A final archive name is published only after verification.

Restore preflights the entire archive before creating any target managed files. Central-directory metadata is bounded and checked before ZIP entry objects are materialized. Only exact canonical manifest-derived source paths are accepted, with no generic extraction of member names into filesystem paths. Reject unknown/duplicate/case-colliding entries, directory/special/link modes, traversal/absolute paths, unsupported schema/fields, invalid UTF-8, bad CRC/content hashes, ZIP64/multi-disk/encryption and unsupported compression. Stored and deflated archives are supported. CRC detects accidental corruption; archives are not authenticated or signed.

Limits are 64 MiB referenced source, 1 MiB manifest, 1,001 entries, 1 MiB central directory and 66 MiB compressed file. Restore retains at most the bounded verified source snapshot in memory before writing; export streams files and then uses the same verifier. Larger workspaces remain editable but need a future larger/streamed backup design. No archive is partially accepted.

Restore rejects a nonempty target before creating its writer lock, acquires the exclusive lease and rechecks emptiness, writes source revisions without overwrite, rechecks staged hashes, then atomically writes the exact manifest last. That manifest is the visibility/commit point. Normal failure or abrupt termination before it can leave a writer-lock file, source directories/revisions or temp files; the folder is not a committed workspace and cannot be automatically retried as empty. Keep those leftovers for inspection and retry in another empty folder. Once the manifest exists, every restored record/source must be complete. Local atomic-rename/file-flush assumptions do not establish power-loss durability.

The old active workspace/lease is replaced only after restore succeeds. Native file/folder pickers supply paths; the renderer's general command channel does not permit export/restore paths. Export requires saved/adopted source and label edits. Restore uses the ordinary unsaved-discard guard and both chooser cancellations preserve the current editor/workspace. Archive operations have a 30-second request deadline; lost/timed-out responses can have completed, so reopen/inspect before retrying. No automatic retries, archive hooks or script execution occur. Scripts execute with user OS permissions only when future runners are explicitly invoked.

This provides portable current-state backup/export and fresh-workspace restore. Loose script import, merging archives into existing workspaces, historical revision retention, automated backup schedules, encryption/signing, persistent SQLite catalog and Windows/release acceptance remain separate work.
