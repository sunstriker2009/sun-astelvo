# ADR-004: bounded session source-word index

Status: selected for the initial source-search batch; persistent SQLite catalog and Windows performance acceptance remain open.

The preview currently admits 1,000 scripts and 256 KiB per source. Implement source search using a bounded in-memory inverted word index in the existing .NET host, with no new native/runtime dependency, cache files or manifest schema fields. Keep the portable manifest and UTF-8 source revisions authoritative. This refines ADR-002's initial search implementation; the proposed persistent/rebuildable SQLite catalog remains later work rather than being claimed as delivered.

Index only active committed source, excluding metadata names, unsaved buffers, deleted scripts, deleted folder trees and orphan revisions. Unicode letters/combining marks/numbers/underscore form words, invariant uppercase supplies case folding, and words over 64 UTF-16 units are omitted. A query supplies 1–8 words, at most 64 units each/120 total; all distinct query words must occur in a source. Punctuation separates words. Quotes, OR, prefix/substring and phrase syntax have no special meaning. The UI explains whole-word AND behaviour and combines results with current metadata/collection filters.

The cache is bound to the exact loaded manifest hash. First search, explicit Rebuild, workspace reopen and any metadata/source commit rebuild it as needed. Each query checks expected revision/manifest freshness and hashes every active source, including warm queries. Build reads one bounded source at a time, validates UTF-8 and committed hash, and rechecks all sources/metadata before publishing the complete cache. Changed/missing/linked/invalid source rejects the operation, drops the cache and publishes no partial result. External content is adopted only through reviewed Reload/Save. The checks detect ordinary edits, including same-length/timestamp-restored edits; they do not create a filesystem transaction against other local processes.

Index budgets are 32 MiB total active-source bytes, 100,000 distinct indexed words and 500,000 word/script pairs. A budget failure leaves editing available and does not publish a partial index. Source text is not retained by the completed cache. Existing 30-second desktop request deadline applies to search/rebuild; a deadline is not a cancellation protocol. Queries make no workspace writes, and process termination merely discards the session cache. Restart always rebuilds.

The renderer hides stale results after any workspace revision change until a new search succeeds. A failed query/rebuild leaves an explicit empty source condition instead of silently widening results. Clear source search returns to metadata filters. Source search is a transient condition separate from saved v5 collection definitions. Script editing/label drafts survive searching. Persistent index/catalog storage, collection source-query predicates, substring/phrase features, Windows measurements and 10,000-record performance acceptance remain open.
