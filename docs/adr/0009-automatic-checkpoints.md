# ADR-009: opt-in automatic checkpoints and normal-close preparation

Status: selected for the timed checkpoint/normal-close batch; Windows and full shutdown/power-loss acceptance remain open.

Extend ADR-008's independent recovery file without changing its format, manifest schemas, host methods or byte limits. The user starts automatic checkpoints explicitly for the current workspace session. A pre-existing checkpoint must first be recovered, manually replaced, or discarded. Reading recovery stops automatic mode and restores this review gate; corrupt/unavailable data cannot be automatically replaced. Automatic mode does not follow workspace changes or renderer restarts.

A small renderer coordinator checks current dirty or externally reviewed tabs about every two seconds. Continuous edits do not restart/postpone the timer. Capture includes inactive source/name/language/folder/tag/favourite drafts and original base hashes. One immutable JSON snapshot is dispatched at a time, using the latest acknowledged raw-file token. Unchanged snapshots are skipped. A clean tab set retains the previous checkpoint instead of automatically deleting it. Automatic replacement represents the current dirty-tab set; records saved/closed/discarded since the prior checkpoint can be omitted from a later replacement. It does not commit source or portable metadata.

Foreground commands first drain any dispatched checkpoint write. Timer dispatch is deferred while a foreground command is busy. Workspace create/open/close and archive restore flush the latest snapshot before the ordinary discard/picker flow can release the old lease. Cancellation keeps the current workspace and automatic mode intact. Successful workspace changes stop timing, clear old recovery state and read the new workspace. Read/recover/discard/manual checkpoint actions stop automatic mode; their tokens/snapshots come from the latest drained result rather than stale render closures.

Any capture/write/timeout/token/size failure pauses timing without automatic retry and retains live drafts plus prior recovery data. The panel summary reports automatic pause. Read/review the checkpoint before starting again. A failed flush blocks the transition/close attempt until the user reconciles recovery or explicitly stops/reviews automatic mode; ordinary editing and saves remain available. A lost response may already have committed, so reread rather than reusing a guessed token.

Normal window close now uses a narrow main-to-preload-to-renderer preparation signal with a fresh correlated ID. Main prevents closing until the renderer drains/flushed automatic work and acknowledges readiness. Foreground work or failed flush returns false, leaving the window/host open. Pending duplicate closes share one preparation; old, malformed or untrusted acknowledgements cannot close a later attempt. A 12-second deadline keeps the window open and reports a postponed close. The existing beforeunload/native discard guard still runs after readiness; cancelling it resets the close permit and retains the host/lease. Host shutdown follows actual window closure. No arbitrary renderer channel, path or executable access is added.

A checkpoint acknowledgement covers that captured snapshot only. Timers are subject to renderer scheduling; force kill/crash, reload, OS shutdown deadlines or power loss can occur before the latest write. Normal close preparation does not promise interception of every shutdown path. Recovery remains explicit, undo/view state is not restored, checkpoints are not encrypted or included in saved-state archives, and Windows/packaged/clean-machine/manual acceptance remain open. Future scripts still run with user OS permissions; renderer isolation is not their security sandbox.
